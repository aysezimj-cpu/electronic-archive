# 📁 Электронный архив документов

Учебный проект по дисциплине «Информационная безопасность» (2 курс).
Вариант 17: веб-приложение для хранения, поиска и учёта документов организации с разграничением прав доступа.

## Возможности

- 📄 Просмотр списка документов и поиск по названию
- ➕ Добавление документов с прикреплением файла (PDF, DOC, DOCX, XLS, XLSX, TXT)
- ✏️ Редактирование и 🗑 удаление документов
- 🔐 Разграничение прав доступа: обычный пользователь (просмотр и скачивание) и администратор (полный доступ)
- 📥 Скачивание прикреплённых файлов

## Технологии

| Компонент       | Технология              |
|-----------------|--------------------------|
| Backend         | Python, Flask            |

## Модель данных

**users** — учётные записи пользователей системы (id, username, password [хэш], role).

**documents** — карточки документов архива (id, title, category, author, description, filename).

Прямой связи между таблицами нет: документ не хранит ссылку на пользователя, который его добавил.

## Установка и запуск

```bash
# 1. Клонировать репозиторий
git clone <ссылка на репозиторий>
cd ElectronicArchive

# 2. Создать и активировать виртуальное окружение
python -m venv .venv
.venv\Scripts\activate      # Windows
source .venv/bin/activate   # Linux / macOS

# 3. Установить зависимости
pip install flask flask_sqlalchemy

# 4. Запустить приложение
python app.py
```

После запуска приложение доступно по адресу `http://127.0.0.1:5000`.

При первом запуске автоматически создаётся:
- база данных `archive.db`;
- учётная запись администратора (логин и пароль заданы в `app.py`, при первом входе рекомендуется сменить пароль);
- несколько демонстрационных документов для наглядности интерфейса.

## Реализованные средства защиты информации

- **Хэширование паролей** — пароли пользователей хранятся в базе данных не в открытом виде, а в виде хэша (`werkzeug.security.generate_password_hash`), проверка при входе — через `check_password_hash`.
- **Разграничение прав доступа (RBAC)** — доступ к маршрутам добавления, редактирования и удаления документов защищён декоратором `admin_required`, который проверяет роль пользователя в сессии.
- **Управление сессией** — авторизация реализована через серверные сессии Flask (`session`), а не через хранение чувствительных данных на стороне клиента.
- **Валидация загружаемых файлов** — сервер проверяет расширение файла по белому списку допустимых форматов (`ALLOWED_EXTENSIONS`) перед сохранением.
- **Безопасное имя файла** — имена загружаемых файлов обрабатываются функцией `secure_filename`, что исключает запись файла по произвольному пути на сервере (защита от path traversal).
- **Ограничение размера загружаемого файла** — установлен лимит `MAX_CONTENT_LENGTH`, предотвращающий загрузку чрезмерно больших файлов.

### Известные ограничения (для учебного проекта)

Эти пункты сознательно оставлены упрощёнными и могут быть отмечены в отчёте как направления для дальнейшего усиления защиты:
- секретный ключ Flask и пароль администратора заданы непосредственно в коде, а не через переменные окружения — для учебного стенда это допустимо, но для реального продакшн-развёртывания их следует вынести в конфигурацию окружения (`.env`) и исключить из репозитория;
- при запуске используется режим отладки Flask (`debug=True`), который не предназначен для продакшн-среды;
- отсутствует ограничение количества попыток входа (защита от подбора пароля).
